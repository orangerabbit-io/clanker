# clanker Phase 1 (Chat MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase 1 of clanker per the spec: a KMP + Compose Multiplatform app (Android + iOS) with OAuth BYOK connect to OpenRouter, streaming chat with model picker, `web_search`/`web_fetch`/`datetime` server tools, wire-faithful SQLDelight persistence, spend-cap enforcement, and guardrails on by default.

**Architecture:** Two Gradle modules: `shared` (pure Kotlin: model, network, agent policy, persistence, security) and `composeApp` (Compose Multiplatform UI with Android + iOS entry points). The domain model is wire-faithful: every persisted assistant message stores its raw response JSON alongside typed fields, so opaque reasoning payloads round-trip verbatim and later API surfaces (Responses/Messages) never need a migration. OpenRouter executes server tools; the client only tracks policy (per-chat toggles, spend caps) and renders results.

**Tech Stack:** Kotlin 2.3.x, Compose Multiplatform 1.9.x, Ktor Client 3.5.x (SSE via byte-channel parsing), kotlinx.serialization 1.9.x, SQLDelight 2.1.0, Koin 4.1.0, kotlinx-coroutines 1.10.x, multiplatform-markdown-renderer-m3. Versions verified in Task 1 and bumped only if a newer stable is verified there.

**Spec:** `docs/superpowers/specs/2026-09-23-clanker-v2-design.md` (executors read both; this plan implements §5 Phase 1 only)

## Global Constraints

- Kotlin 2.3.x pin (verify exact patch in Task 1; do not silently upgrade majors).
- Compose Multiplatform 1.9.x; compose compiler plugin versioned with Kotlin (`org.jetbrains.kotlin.plugin.compose`).
- Ktor Client 3.5.x, OkHttp engine on Android, Darwin engine on iOS.
- All network calls HTTPS only — reject `http://` base URLs at construction.
- Secrets never in plaintext storage; BYOK key wrapped by platform secure storage (Android Keystore / iOS Keychain) behind `expect/actual`.
- Persisted messages are wire-faithful: raw JSON stored verbatim next to typed fields.
- Every request carries: `usage` (automatic), spend cap fields from policy, guardrail defaults on (prompt-injection detection, secret redaction).
- Conventional commits (`feat(scope):`, `test(scope):`, `chore(scope):`); one logical change per commit.
- CI must run `shared` JVM tests + Android build on every push before any PR merges.
- CI/CD from day one: every merge to `main` produces a **signed release APK attached to the GitHub Release** (semantic-release tags the release), installable via Obtainium against the public repo. Release APK is signed with a real keystore supplied via GitHub secrets — never the debug key — so Obtainium in-place updates succeed across releases.
- PR builds also produce a debug APK artifact for pre-merge testing.
- Worktrees land on `feature/phase1-chat` via the normal PR gate; no direct pushes to `main` once CI exists.

## Review Focus

Failure modes the spec implies but unit tests may miss — each is pinned by the named task's test:

1. **SSE dies mid-stream (network drop, app background).** Partial assistant content must be preserved and marked `Interrupted`, never lost or double-rendered. Test: Task 6 `sse partial failure marks interrupted`.
2. **Final usage chunk missing/cost null.** UI must show "cost unavailable", not crash or show $0.00. Test: Task 6 `usage absent yields null cost`.
3. **Reasoning with opaque payload.** A reasoning block carrying `signature`/opaque data must round-trip byte-identical through persist→load→resend. Test: Task 2 `reasoning opaque round trip`, Task 3 `wire faithful round trip`.
4. **Key store failure degrades to plaintext.** If platform secure storage throws, connect must fail closed with an error, never fall back to plaintext. Test: Task 4 `keystore failure fails closed`.
5. **Spend cap reached mid-agent-run.** Terminal state "spend cap reached" with everything gathered so far rendered; no silent truncation, no retry loop. Test: Task 10 `spend cap produces terminal state`.
